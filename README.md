# shazam-wasm

A browser WebAssembly port of [`shazamio/shazamio-core`](https://github.com/shazamio/shazamio-core) at commit `f6076da` (2026-11-01). It turns audio bytes into the signature Shazam's tag endpoint accepts.

Opus is deliberately not included. Upstream decodes Opus through the C `libopus` library. Every other upstream codec goes through pure Rust Symphonia and is included.

This package does not talk to Shazam. It only makes the signature. The lookup belongs in the Recognition Worker.

## Build

Needs Rust 1.87 or newer, the WASM target, and `wasm-pack`.

```bash
rustup target add wasm32-unknown-unknown
bun run build:wasm
bun run build:oracle
```

`build:oracle` builds the native reference binary used by the parity test.

## Use

```ts
import { initialize, recognizeBytes } from 'shazam-wasm'

await initialize() // browser: fetches the WASM beside the JS
const bytes = new Uint8Array(await file.arrayBuffer())
const signature = await recognizeBytes(bytes, { seconds: 12 })

console.log(signature.uri)       // data:audio/vnd.shazam.sig;base64,...
console.log(signature.samplems)  // 12000
```

In Node or a test, pass the WASM bytes to `initialize`:

```ts
import { readFileSync } from 'node:fs'
await initialize(new Uint8Array(readFileSync('rust/pkg/shazam_wasm_bg.wasm')))
```

`seconds` defaults to 12. A file shorter than the window is fingerprinted whole. `seconds: 0` is refused.

## Errors

`recognizeBytes` throws `ShazamError` with a stable `code`:

- `unsupported_opus`
- `invalid_segment`
- `decode_failed`
- `signature_failed`
- `init_failed`

## Formats

Included: MP3, MP2, FLAC, WAV, AIFF, CAF, OGG Vorbis, AAC, M4A, ALAC, ADPCM, PCM, Matroska/WebM containers, and the other codecs Symphonia ships.

Excluded: Opus, including Opus in OGG and Matroska. The error is `unsupported_opus`.

## Tests

```bash
bun test test/smoke.test.ts       # API and typed errors
bun test test/parity.test.ts      # native oracle comparison
```

The built WASM in `rust/pkg` is committed, so the smoke test runs without a
Rust toolchain. Rebuild it after changing the Rust source. The parity test needs
the native oracle, so it needs Rust.

The test compares the sample length against the native oracle for every
non-Opus fixture, checks the exact URI for the deterministic set, and checks the
five known macOS URI differences. This is stricter than Shazam matching without
pretending that floating-point output is identical across targets.

Current parity on macOS:

- Match: `chord.flac`, `alac.m4a`, `mp2.mp2`, both ADPCM WAVs, all PCM files, `chained_capacity.ogg`, `ac3_then_flac.mka`.
- Differ: `probe.flac`, `probe.mp3`, `probe.ogg`, `probe.m4a`, `aac.aac`.

Those differences are the platform floating-point issue upstream documents. Symphonia decodes MP3 and OGG in `f32`, and `rubato` builds its sinc table from the platform's `sin` and `cos`. The WASM build uses a different libm, so a few peaks land one quantisation step apart. The sample counts still match. This is why upstream pins its FLAC golden only on Linux and only tests durations on macOS and Windows.

If exact cross-platform URI parity is required, the resampler has to become deterministic before this test can pass.
